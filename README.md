# GREY CLOUD · 字符音墙

用一首曲子的实测频谱结构驱动 ASCII 画面。**云的形状不来自审美，来自曲子自己。**

三件作品：

| 文件 | 说明 |
|---|---|
| `grey_cloud_ascii.html` | 主件。6 个深度层按 Beer-Lambert 累积消光的 ASCII 音墙 |
| `grey_cloud_3d.html` | 团块版。云是 3D 空间里的离散 billboards，针孔投影 + 按视空间 Z 排序遮挡 |
| `风卷残云.html` | 同一情绪的静态照片动态化 |


## 打开

单文件、无构建、无依赖，本地浏览器双击即可（建议 Edge / Chrome）。

| 方式 | 说明 |
|---|---|
| 双击打开 → 点击画面 | 播放音频，画面与 `audio.currentTime` 严格同步 |
| `?demo=1&t=150` | 免音频，按烘焙曲线从第 150 秒跑。用于逐时刻验收、录屏 |
| `?live=1` | 走 WebAudio 实时分析。换别的曲子时才需要 |

**音频不随仓库分发**——《Grey Cloud》是 James Primate 的商业曲目，我不再分发别人的音乐。要跑第一种模式，自己放一首 `Grey Cloud - James Primate.mp3` 到本目录。`?demo=1` 不需要音频文件，因为曲线已经内联进 HTML（`file://` 下 `fetch` 被 CORS 拦，所以数据和音频都走内联）。

## 映射

画面纵轴 = 频率。低频在下堆成块，高频在上拉成丝。

依据是对这首曲子的实测：

- 中频全程满格，总能量稳态动态**仅 8.9 dB** → 这是一堵音墙，不是叙事曲。推进靠音色堆积，不靠音量。
- 高频包络 20–100 s ≈ 62 → 140–190 s ≈ 85 → >210 s ≈ 15（归一化）。云越压越实，然后塌掉。
- 低频被抽空的事件实测 14 处（0.1–0.3 s、9–18 dB），是这堵墙唯一的呼吸 → 画成云裂开、泄出天光。
- 215 s 起整体坍塌，231 s 归零。

字符阶梯两档：`" .·:,;-"`（高频未起时细碎）/ `"·:+=*#▓█"`（高频堆积时密实）。

鼓点 = 云内放电。闪电走「格子路径」——每步只在字符网格里落一个符号，符号按斜率取 `| / \ -`，保持 ASCII 语法；余辉半径随寿命外扩、字符同时从 `*` 退到 `·`。

云是 6 个深度层（13 km → 0.5 km），按 Beer-Lambert 累积消光：近处挡住远处，远处只从缝隙里露出来。**纵深来自遮挡，不来自层数**——早先 12 层纯相加，实测各层贡献线性可加，等于没有一层挡住过另一层，看着只有一层。

## measure/

出图前所有数字都从这里来，可复现。

| 脚本 | 作用 |
|---|---|
| `bake_curves.py` | 从 mp3 重烘焙频谱曲线并注入 HTML（一条命令） |
| `bake_stems.py` | 鼓点起始、k-means 音色分类、脉冲通道，注入 HTML |
| `measure_photo.py` | 辅件的实测依据：山脊线、云丝倾角场、航迹拟合、采样调色板 |
| `multi_view.py` | 多视口验收：铺满没有、帧率、运行时报错、出图 |
| `flash_test.py` | 连拍量化"云在涌"还是"整幅在闪" |
| `halo_test.py` | 量闪电余辉是外扩消失还是向内收缩 |
| `parallax_test.py` | 冻住动画、逐层单独合成，量每层视差位移 |
| `luminance_trace.py` | 沿时间轴复现轨迹，查"画面比声音先塌"这类问题 |
| `sync_data.py` | 把实测数据从主件同步到团块版（单一来源，避免两份曲线漂移） |
| `render_video.py` | 逐帧驱动渲染成视频（手工时钟，不靠实时帧率） |

跑脚本需要：`python` + `playwright`（用 `channel="msedge"`）+ `imageio-ffmpeg` + `numpy` + `pillow`。

帧率必须在**真视口**里量：无头或后台页面 `visibilityState=hidden` 会把 rAF 节流，实测同一页面假报 0.3 fps、真视口 120 fps。

## 团块版 `grey_cloud_3d.html`

`grey_cloud_ascii.html` 交付后留下的问题是：**立体感还是出不来**。视差位移量测下来是成立的（最远 24 px、最近 207 px，与设计值吻合），所以病不在机构——在于那 6 层是**无界的同分布 2D 噪声**，每层都铺满整幅，没有任何轮廓边。位移要有东西被移，眼睛得能在层间找到同一个对象。

这一版把云改成 3D 空间里 240 个离散团块：每个有真实 `(x,y,z)`、半径、消光截面；针孔投影（近大远小是算出来的）；按**视空间** Z 由近及远泼溅，逐格维护累积消光 τ，可见密度 = d·e^(-τ)。遮挡因此是几何的结果，轮廓边自己出现。相机只绕竖直轴转，不做俯仰——那会把"画面纵轴=频率"甩歪。

**音色的脉冲性质**这次落在团块上：从实测鼓点起始按 k-means 三类各自合成指数衰减包络（τ = 0.26 / 0.14 / 0.065 s，分别对应 kick / snare / hat），团块按所属频段归到一类，该类一响它就鼓胀变亮。上一版做不到这件事，因为根本没有可分立的对象。

团块内部纹理用一张共享噪声瓦片按团块自身偏移采样，所以细节**跟着团块一起转**，不是贴在屏幕上。1920×1080 下页面自身跑约 105 fps，比 6 层逐格 fbm 的主件还快一倍。

## 已知不足

- **团块版还没收口。** 轮廓与前后遮挡成立了，但下半部过密糊成一片，云底被压到画面底部导致雨和标题几乎看不见；远处稀疏区仍有规则 `+` 点阵。它现在是一个成立的**实验**，不是一件完成的作品。
- 团块版里"画面纵轴=频段"是靠团块的 y 位置维持的，转相机时允许跨行漂移。这是有意的取舍：换到 3D 就必须放弃行与频段的严格对齐，换来的是频段有了前后景深。
- 渲染**不可复现**：雨滴落点与闪电几何走 `Math.random`，同一段时间渲两遍平均差 32/255，每条都是独立的一次演奏。团块本身已用播种固定（`mulberry(20261006)`），但雨和闪电还没有。
